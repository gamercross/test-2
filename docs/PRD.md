## 처음 말한 것

> 1. 미션 소개 Python에서 API를 호출한다는 게 처음엔 막막하게 느껴집니다. 그런데 한 번 연결되는 순간, 가능성이 달라집니다.  LLM API가 추천을 하고, 지도 API가 위치를 찾고, 최종 리포트가 생성되는 흐름 — 이걸 손으로 조합합니다.  단일 API 호출이 아니라 여러 API를 엮어 인사이트를 만드는 과정, 그게 이번 미션입니다.  현대 서비스의 대부분은 API를 통해 데이터를 주고받습니다. AI 기능, 지도 데이터 등 다양한 서비스를 API로 손쉽게 연동할 수 있습니다.  이 미션에서는 LLM API와 지도 API를 조합하여 국내 여행 추천 프로그램을 개발합니다. 사용자가 여행 날짜를 입력하면, LLM이 해당 시기에 여행하기 좋은 지역을 추천하고, 지도 API로 맛집 정보를 검색한 뒤,

## 1. 문제와 목표 — 1단계

- **불편** — 여행 날짜에 어디가 좋은지, 맛집은 어디인지 하나하나 찾아봐야 해서 번거로워요.
- **달라지는 것** — 날짜만 넣으면 추천 지역과 맛집, 1일 일정이 담긴 여행 리포트가 만들어져요.
- **누가** — 여행 날짜를 입력해서 국내 여행 리포트를 받아 보는 사용자예요.
- **크기** — 크기: 보통 — AI와 지도 서비스를 불러 이어 쓰는 흔한 방법 하나로 풀려요.

## 2. 아이디어와 범위 — 2단계

- **빈칸 채우기** — 누구: 여행 날짜를 넣고 국내 여행 리포트를 받아 보는 사용자 · 불편: 날짜에 맞는 지역과 맛집을 하나하나 찾아봐야 해서 번거로워요 · 해결: 날짜만 넣으면 추천 지역, 맛집, 1일 일정이 든 리포트를 만들어 줘요 · 어디까지: AI와 지도 서비스를 이어 쓰는 리포트 만들기까지 · 언제 성공: 아직 모름
- **왜 · 어디까지 · 언제 성공** — 왜: 여행 지역과 맛집을 따로 찾는 번거로움을 줄이려고요 · 어디까지: 날짜 넣기, 지역 추천, 맛집 검색, 리포트 만들기까지(이번에 안 하는 것: 아직 모름) · 언제 성공: 아직 모름
- **한 문장 한 가지** — 사용자가 여행 날짜를 넣으면, 앱은 그 시기에 가기 좋은 지역을 추천한다 / 지역이 정해지면, 앱은 지도 서비스로 맛집을 찾는다 / 추천과 맛집이 모이면, 앱은 1일 일정이 담긴 여행 리포트를 만든다
- **남의 정보 · 밖으로** — 남의 정보: 없음(여행 날짜만 받아요) · 밖으로 나가는 것: 여행 날짜와 추천 지역이 AI 서비스와 지도 서비스로 나가요

## 3. 꼭 필요한 기능 — 3단계

- **기능 문장** — 사용자가 여행 날짜를 넣으면, 앱은 그 시기에 가기 좋은 지역을 추천한다 / 지역이 정해지면, 앱은 지도 서비스로 맛집을 찾는다 / 추천과 맛집이 모이면, 앱은 1일 일정이 담긴 여행 리포트를 만든다
- **숫자로** — 리포트가 만들어지는 시간 → 아직 모름 / 맛집 개수 → 아직 모름 / 성공 기준 → 아직 모름. 숫자를 정하지 못한 건 억지로 정하지 않아도 돼요.
- **꼭 · 있으면 좋음** — 날짜 넣으면 지역 추천: 꼭 / 지역 맛집 찾기: 꼭 / 1일 일정 리포트 만들기: 꼭
- **나온 곳 잇기** — 기능이 3개라 아직 안 해도 돼요
- **막을 일** — 여행 날짜를 넣으면, 앱은 날짜 말고 다른 개인 정보를 받거나 밖으로 보내지 않는다

## 4. 만드는 방법 — 4단계

- **후보 찾기** — 서버가 있는 웹 / 화면 하나짜리 웹 / 표 계산 도구
- **견주기** — 서버가 있는 웹: 열쇠를 숨기고 AI·지도를 이어 쓰기 좋아요 · 화면까지 만들 게 늘어요 / 파이썬 프로그램: 날짜 넣고 리포트 받기까지 가장 빨라요 · 글자 창이라 보기엔 소박해요 / 휴대폰 앱: 여행 중에 꺼내 봐요 · 만들고 올리기 번거로워요
- **고른 까닭** — 고른 방법: 서버가 있는 웹 — 까닭: 날짜만 넣으면 AI와 지도 서비스를 뒤에서 이어 부르고, 열쇠도 안전하게 숨길 수 있어서요
- **약속과 맞대기** — 쓸 도구: 맞음 — AI와 지도 서비스를 이어 쓸 수 있어요 / 하면 안 되는 것: 맞음 — 날짜 말고 다른 개인 정보는 받지 않아요 / 화면 원칙: 아직 모름
- **보는 사람 · 둘 곳** — 누가 무엇을 보나: 사용자 본인이 자기 리포트만 봐요 · 정보를 둘 곳: 서버(날짜와 추천 지역은 AI·지도 서비스로 나가요) · 들어올 때 확인: 불필요

## 5. 뼈대와 할 일 — 5단계

- **끝까지 잇기** — ① 여행 날짜를 넣어요 → ② AI가 가기 좋은 지역을 추천해요 → ③ 지도 서비스로 그 지역 맛집을 찾아요 → ④ 1일 일정이 담긴 여행 리포트를 보여줘요
- **도는지 보기** — 화면에 여행 날짜를 넣고 버튼을 눌러 보면 → 추천 지역, 맛집, 1일 일정이 담긴 리포트가 화면에 나오면 된다
- **작게 나누기** — 날짜 입력 화면 만들기 / AI에게 지역 추천 받기 / 지도 서비스로 맛집 찾기 / 1일 일정 리포트 글 만들기 / 리포트를 화면에 보여주기
- **비밀값 검사** — AI와 지도 서비스의 열쇠는 .env 파일에만 두고, 그 파일은 올리지 않게 막아요. 올리기 전에 열쇠 글자가 코드에 남았는지 검사해요. 열쇠는 서버에서만 써요.

## 6. 만든 것과 확인 — 6단계

- **확인 먼저** — 날짜로 지역 추천 — 여행 날짜를 넣으면 가기 좋은 지역이 나와야 해요 / 맛집 찾기 — 그 지역을 넣으면 지도 서비스의 맛집이 나와야 해요 / 리포트 만들기 — 추천과 맛집이 모이면 1일 일정 리포트가 나와야 해요
- **작은 확인** — 날짜 입력 화면 — 날짜를 넣을 수 있어요 / 빈칸이면 안내가 나와요 / AI 지역 추천 — 지역 이름이 나와요 / 지도 맛집 찾기 — 맛집이 하나 이상 나와요 / 리포트 — 추천·맛집·1일 일정이 모두 들어 있어요
- **써 보기** — ① 사용자가 여행 날짜를 넣고 버튼을 눌러요 → ② 앱이 가기 좋은 지역을 추천하고 그 지역 맛집을 찾아요 → 결과: 추천 지역, 맛집, 1일 일정이 담긴 리포트가 화면에 나와요
- **비밀값 검사** — AI와 지도 서비스의 열쇠는 .env 파일에만 두고, 그 파일은 올리지 않게 막아요(.gitignore). 올리기 전에 열쇠 글자가 코드에 남았는지 검사하고, 열쇠는 서버에서만 써요.
